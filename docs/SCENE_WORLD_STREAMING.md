# Static transforms and actor-cell streaming

The existing actor, component, prefab and scene APIs remain available. Static actors reuse their transform publications until their pose, descendants or render objects change. Large worlds can opt into independently cooked actor cells through `WorldStreaming`.

## Automatic setup during mesh import

Select the source mesh asset in the Editor and expand its MeshResourceDirector `streamingOptions` group. `enabled` defaults to **false**, including existing import settings that have no streaming group. To generate a streaming prefab:

1. Enable `streamingOptions.enabled`. Set `cellSize` (default 256) and `maxActorsPerCell` (64) for the imported asset's cell grid. Set `loadRadius` (512) and `retainRadius` (768) in world units after prefab placement. Keep retain at least as large as load; account for the source import scale when choosing distances.
2. Choose `enableHlod` and `previewEditorCamera` (both default true within the disabled group). HLOD generates coarse building-bounds skyline proxies; it does not preserve facade detail or textures.
3. Click **Save**, then **Import**. The read-only **Import Status** field reports queued/running work, completion, cancellation or the failure reason; hover its label to read a long message. The importer first writes normal converted mesh assets, cooks a unique generation under `Cache/Worlds/<source hash>/<generation>/`, and atomically publishes the cached prefab after cooking succeeds. A failed cook reports the cell/group and its actual count or size limit, and identifies a retained previous prefab when one exists. Import progress is transient and is not saved as import configuration.
4. Insert the source asset into the scene again. The new prefab is a thin actor with a configured `WorldStreaming` component; already placed detailed instances are not rewritten. The generated component references the project-relative manifest and enables `Instance World`, `Follow Active Camera`, and the chosen Editor preview setting. No manual CLI cooking or component attachment is required.
5. Inspect the component's resident-cell/actor counts and `Streaming Error`. Outside Play it uses the Editor camera when preview is enabled; during Play it follows an enabled active Camera in the same scene. An explicit `Observer` takes priority. With no eligible camera it uses the prefab owner.

For `new_york_3.glb` imported at scale 100, the native validation uses `cellSize=25600`, `maxActorsPerCell=64`, `loadRadius=51200`, and `retainRadius=76800`, with HLOD enabled. Its runtime check sets the generated component's `Maximum Resident Actors` to 128 and `Maximum Resident Cells` to 8; these test limits are separate from the import defaults.

Moving, rotating or scaling the prefab places its streamed contents; duplicate instances use separate actor/component identities while sharing asset resources. Streaming radii remain in world units. Scene saves retain the world reference and omit resident cell actors. Session edits to streamed contents remain in memory overlays; persist permanent changes in the source assets or a separate save system.

Automatic conversion makes render-only imported groups static and flattens componentless grouping nodes where safe. Animated, scripted, physical, unknown-component and externally referenced groups remain persistent. One inseparable oversized group fails cooking instead of being silently split. A single monolithic mesh remains one streaming unit; author separate building/block objects for useful spatial streaming. Initial import builds the source authoring graph and converted caches once; normal prefab use reads the cooked cells.

A failed cook or prefab publication leaves the previous cached prefab and its world generation reachable. Normal mesh/material conversion still uses the existing shared cache, so this is not a transaction over all imported asset dependencies. Old and failed world generations remain on disk until safe cleanup. Keep the manifest, cells, proxy meshes and converted asset dependencies together when moving or packaging the project. Turning `enabled` off, saving and reimporting restores the normal detailed prefab for future insertions. Import settings do not override the application's shared CPU/GPU budgets.

When buildings appear missing, compare the placed component's **World Manifest** with the newly published prefab first. Changing the import scale or completing another import does not update an already-placed component. Its radii and camera clip distances must also match the generation's world units. Raising radii over a finely divided old world can exceed its resident cell/actor limits; use an appropriately cooked grid and keep HLOD coverage inside those limits. The Editor camera's orbit target must be within its far clip distance to see the target.

An enabled Skybox with six empty face slots deliberately uses the bundled checker texture. Assign a complete authored sky or disable that unconfigured skybox to use the camera clear background. This checkerboard is independent of missing city geometry. Existing material documents are preserved and cataloged on import even when material overwriting is disabled; unresolved texture UUIDs in an older authored document still require an explicit dependency repair.

Texture assets expose saved `size` and `mipmapFilter` import options. Raw JPEG loading now honors the maximum dimension through scaled JPEG decoding before admitting retained pixels, with a bounded final reduction for non-power-of-two images. Unconfigured raw sources retain their original dimensions. Oversized non-JPEG sources need a cooked or resized input for this path. `mipmapFilter` defaults to `None`; use `Colour` for diffuse/albedo images, `Normal` for normal maps, and an appropriate data filter for other maps. Physical mip chains belong to the shared texture recipe; material `uvFilter` and `uvAniso` select sampling. Save the recipe before a cold load/reload. Texture Save/Import dispatch now applies edited options before invoking the action once.

## Cooking a city

Build the `WorkphoneSceneWorld` target. Import the GLB normally once to produce the engine's prefab, meshes, materials and textures, then cook that prefab offline:

```powershell
WorkphoneSceneWorld.exe INPUT.prefab OUTPUT_DIRECTORY --asset-root PROJECT_DIRECTORY --cell-size 256 --max-actors 64 --render-only-static --hlod
```

The tool writes `world.wpworld`, independent `.wpcell` payloads and `world-preview.fbscene`. It never changes the input prefab or GLB. `--render-only-static` explicitly permits converting render-only groups and flattening componentless grouping nodes while retaining world poses. Without it, only explicitly static render-only groups become disposable cells. Scripted, physical, animated, externally referenced and unknown-component groups stay in the persistent layer. An inseparable persistent group that exceeds the cell limits is rejected.

Geometry bounds determine cell ownership, including meshes with all actor positions at the origin. A building has one owner and expanded coverage bounds; it is not copied into every overlapping grid square. Actor/component UUIDs and existing asset references are retained. The manifest is published only after all new payloads are written, so a failed cook leaves the previously published generation usable. Repeated cooks currently leave older generated payload files on disk; remove obsolete generations only when no running world uses them.

Use project-relative asset paths and place the output under the project directory for relocation. Package the manifest, its referenced payloads, the existing cooked mesh/material/texture dependencies and their resource catalog. Runtime consumes cooked files, not the source GLB. This version reads loose world files through the filesystem; world files inside archive packages require an additional I/O adapter.

`--hlod` opts into coarse skyline proxies. The cooker emits one batched bounds-box mesh and a separate proxy cell for each eligible detail cell. This preserves building extents with a much smaller actor count; it does not preserve facade textures or detailed silhouettes. HLOD output must be under the asset root so generated mesh references remain portable. The version 2 manifest records explicit detail/proxy links, and the reader still accepts version 1 worlds.

The mesh-director workflow registers generated HLOD mesh resources in the project catalog before publishing its prefab. A standalone CLI cook writes those files without updating a running project's catalog. Before previewing CLI-generated HLOD, index that output folder with `fileSystem->addFolder(outputDirectory, true)` and import it through `resourceDatabase->importFolder(outputDirectory)` in the same project. Runtime resource lookup requires those mesh identities and does not import missing assets.

## Editor and runtime

Load `world-preview.fbscene` in the Editor. Its persistent `WorldStreaming` component explicitly uses the Editor camera for preview demand. For gameplay, attach the component to a persistent player/interest actor, or assign its `Observer` property, and disable `Preview Editor Camera`. The component runs on the scene owner task and opens `World Manifest` relative to the project directory.

The native `SceneWorldStreamer` API accepts up to eight interest positions per update. Gameplay, collision and spectator interests must be combined deliberately; preview-camera demand should not replace gameplay demand.

For a world cooked with `--hlod`, enable `Enable HLOD` on the component (native `enableHlod`) and set `Proxy Load Radius` / `Proxy Retain Radius` beyond the detail retain radius. Proxies use the same scheduler, live actor/cell limits and install budget as details. Both representations must fit during a handoff; insufficient headroom retains existing coverage and increments `hlodAdmissionFailures`. `residentProxyCells`, `visibleProxyCells` and `representationSwitches` expose HLOD state. Pinned or dynamic detail cells remain detailed; proxy identities are disposable.

Handoffs wait for detailed graphics objects to load; with an active Claw DX11 renderer, mesh load now admits geometry on the GPU before publishing `Loaded`. The coordinator retries unloaded target graphics objects through the existing queue, at most eight requests per update with a 250 ms per-cell backoff; `graphicsRetryRequests` records those requests. Material texture uploads remain lazy, so this readiness boundary covers geometry rather than complete material fidelity. An edit to a detailed cell invalidates its baked proxy for the open session: distant demand uses the detailed edited overlay, and leaving both radii still allows ordinary eviction and later restoration.

Configurable controls include load/retain radii, actor/cell residency limits, pending requests, minimum residency, install count and install time. Radius hysteresis and minimum residency reduce boundary churn. Teleports replace obsolete requests. The scheduler reads/decodes immutable payloads on its existing workers; the scene owner installs complete bounded groups. Rendering is paused for a cell's graph commit, not for disk reads or the full city.

Installation is atomic at cell granularity. The time limit is checked between cells; a single expensive cell can overshoot it. `installBudgetOvershoots` and `lastInstallMilliseconds` expose this. Reduce cell actor/byte limits when tuning activation latency. Actor admission also checks the existing global actor pool.

Installed roots and their descendants adopt the destination scene's Edit or Play state. This runs the normal component activation path and publishes renderer poses for actors added after initial scene loading. A scene that has not entered either mode keeps its existing loading behavior.

Edits to a disposable cell are compared with its installed baseline before eviction. Changed serialized state is retained in a budgeted in-memory overlay and reapplied on reentry, with the same UUIDs. Overlay allocation failure prevents eviction instead of dropping edits. Overlays last for the open world session; permanent game saves must persist them separately. Making an actor dynamic promotes its cell to retained ownership. `pinActor(uuid)` explicitly retains an actor's cell before gameplay acquires long-lived references. Pinned demand that exceeds capacity reports an error. Closing the world explicitly destroys its owned actors.

Baseline fingerprints exclude the runtime `state` field only from component records, so deferred activation and Edit/Play changes do not create edit overlays. This normalization applies to the hash copy; retained overlay payloads keep their complete component state data.

Scene generation changes cancel late publication. Failed cell reads remain errors until demand changes or the world is reopened. Graphics lifecycle tickets reject cancelled queued loads/reloads and superseded unloads. Retirement retains participating payload reservations until retained graphics objects finish unloading.

After graphics retirement, the mesh manager releases reloadable CPU geometry when only its cache and the retirement transaction own the resource. Cache acquisition uses the same lifecycle lock as eviction. Live components, queued loads, gameplay resource references, direct mesh references and other resources sharing geometry prevent reclamation. External weak references also conservatively pin resources/geometry because they can be promoted independently. Resource UUIDs, settings and paths stay cached for later loading; direct manager load APIs rehydrate evicted entries. Procedural meshes remain resident because they have no reload source.

The graphics owner also sweeps reloadable material and texture caches on every update, after queued unloads and before new load admission. Each manager inspects at most 32 entries with a rotating cursor; retirement and close use the same sweep. Materials retire first so their texture references can be released in the same pass. Cache lookup and eviction share the graphics lifecycle lock. External strong/weak references, explicit load locks and retained material graph nodes prevent destructive reclamation. A material must still match its loaded authoring document, including shader parameters; nonserialized texture facade edits also pin it. Procedural materials, edited materials, render targets and textures without a supported file reload recipe remain resident. Backing sources must still be accessible. Eviction retains cached identity, path and settings, and normal loading rehydrates the same wrapper. A headless close performs bounded sweeps; remaining eligible cache entries need later graphics updates or manager teardown.

Retirement retries identity tickets as external owners release their pins, examining at most 32 candidates per coordinator update. Tickets add no resource references and do not keep decoded cell payloads alive. Closing or destroying a coordinator transfers remaining work to the existing Primary job queue's coroutine path, where each update performs one bounded pass. Pending graphics objects keep their participating source reservations until unload acknowledgement. Without a running job service, close exhausts currently reclaimable CPU work; manager teardown handles remaining pinned resources. This is conservative reclamation, not a total asset memory cap.

The manifest builds a balanced bounds index once when opened. Observer queries visit nearby coverage bounds, with persistent/pinned/resident cells considered separately. Cell ownership remains unique even when geometry crosses many grid squares. Queue batches adapt to the shared scheduler's pending and ready capacities, including a service configured with one queue slot.

## Measurements and limits

`TransformSystem::statistics()` exposes local/world recomputations and unchanged writes. Its revision counters are independent of slot lifetime generations. Clean static subtrees return before visiting components; dirty descendants still invalidate their ancestors. Normal updates consume dirty queues rather than scanning all transform storage. Hierarchy/component membership locks are released before transform callbacks, allowing render capture to acquire them without a lock inversion. Native nodes continue to use the existing C transform/matrix caches and shared graphics lock.

Transform registry allocation/removal locks the complete slot transaction, preserving handles during concurrent cell activation and retirement. Actor transform acquisition retains ownership under the same short gate used for replacement; transform conversion and renderer publication keep that reference through their calls. Removed transforms are released after unlocking. State contexts dispatch retained inventory snapshots and lock duplicate insertion/removal transactions, so concurrent node retirement cannot invalidate the dispatch array.

Scene-node identities are allocated under a shared gate before their states enter the shared context. The Claw camera adapter converts the public degree-based field of view to native radians, and ImGui images use the texture's shader-resource view, including render targets.

Claw mesh material, visibility, shadow and geometry mutations share render capture's graphics lifecycle lock. Application-task activation cannot invalidate a native draw snapshot midway through capture/submission. Resource load/reload keeps its existing dispatch and render-pause ordering.

Factory pools serialize free-slot acquisition with block growth. Concurrent callers cannot consume the last published slot between an emptiness check and allocation, or spin waiting for a fixed-capacity pool to grow.

Scene resource inventory refresh publishes complete snapshots under its map lock. Replaced objects remain retained until after publication unlocks; lookups retain their result before releasing the read lock. Anonymous objects with nil UUIDs are excluded from this lookup cache. This fixes a live Editor failure where concurrent scene refreshes prematurely destroyed transforms still owned by actors. Scene collection appends components directly, avoiding repeated rebuilding of the accumulated array.

Scene membership events coalesce resource refresh into one pending Primary job per database. A concurrent mutation during a scan schedules a follow-up through the existing coroutine service, at most once per later update. Deferred scans verify that their database is still loaded and active before using its catalog. Explicit database refresh stays synchronous. This avoids reloading the catalog and rescanning the entire scene for every actor in an installed cell.

`SceneWorldStreamer::statistics()` reports actor/cell counts, read/install/eviction/failure counts, source payload reservations, pending work, commit overshoots and released mesh/material/texture resources. Material/texture release counts cover shared-cache sweeps initiated by that coordinator and can include assets shared with other worlds. Readers receive the latest completed owner-operation snapshot, so UI inspection does not traverse mutable residency containers. `indexNodesVisited` and `indexCellsTested` describe the most recent observer query. The shared scheduler reports reservations by memory class and its queue capacities. Source/decoded payload sizes are conservative estimates, not measured total process memory.

Normal CPU mesh vertex/index storage and Claw texture payloads now participate in the existing scheduler's `SourceCpu` budget. Each actual buffer owns its lease; mesh/resource aliases do not add another charge. Retained buffer owners keep both data and reservation alive through mesh retirement. Mesh replacement reserves the overlapping old/new storage before committing, and rejected cooked reloads retain the last good mesh.

Claw's native mesh object, vertex/index/submesh capacity and normalized render caches also reserve `SourceCpu` before allocation, through optional callbacks on the existing C mesh API. Clones account for their independent allocations; immutable skin bind data shares its lease, while retained skin output has a separate charge. File/parser buffers, mesh conversion, skin application and DX11 index conversion reserve working storage; replacement growth includes overlapping generations and preserves the previous allocation on denial. Unbudgeted C callers retain the existing API behavior.

File texture decoding admits encoded data, header inspection and decoded/conversion storage before full decode. Formats must support header-only inspection; unsupported codecs require conversion or cooked texture input. Pixel dimensions and arithmetic are validated against the admitted header. Decoder working allowances include original and converted images, but codec-private metadata/scratch and allocator overhead are not bounded by those reservations. Manual texture initialization allocates its admitted final pixel buffer directly; denied replacements preserve the previous pixels, dimensions and native view. Published immutable material render versions own `SourceCpu` reservations through their retained readers; expired weak handles release the snapshot charge. Material parsing has a 1 MiB source-descriptor limit and a preparation allowance, and reloadable materials retain a charged serialized authoring baseline.

Claw-owned native material descriptors, packed texture-name tables/strings and optional native callback blocks now reserve `SourceCpu` before allocation. Descriptor replacements admit overlapping old/new storage and preserve values, borrowed names and revisions on denial. Native clones inherit the allocation policy and charge independent copies; copying into an existing descriptor uses its destination policy. The ordinary C constructor remains available to unbudgeted callers. Meshes and materials share the native allocation-local admission helper, including their native allocation headers.

Persistent Claw material preparation stores also participate: shared store/control-block allocations, record pages, page-pointer arrays and identity-map nodes/buckets carry allocation-local leases. Draw publications admit their dense record/owner/binding/sort arrays, lookup tables and pool chunks through the same shared service. Alignment padding and budget headers are included in admission. Cache aliases and publication leases share physical storage without duplicate charges. Cleared reusable capacity remains charged until freed, including cached pool chunks; a final cache/publication owner releases those allocations. Existing table inventory APIs exclude allocator headers; scheduler usage includes the budget headers and is authoritative for admission. Failed capture growth exposes no partial mesh binding, existing sealed records remain usable, and direct/scene draw paths defer denied metadata allocation for retry.

Material authoring now admits technique/child/pass/texture-slot collections, optional legacy surface and texture-facade blocks, unresolved names, shader IDs/texture references/binding arrays, primary-pass selections and immutable cube-face snapshots. Shared shader layouts pre-admit descriptor/name/lookup/default capacities; effective copy-on-write parameter edits admit the copied value capacity before publication. Copies share their physical leases, retained snapshots keep their buffers charged, and denied replacements preserve the previous published values and revisions.

Material/texture wrappers, authoring nodes and material state objects opt into the existing allocation policy for direct, factory and pooled construction. Entire asset pool blocks remain charged while retained, including unused slots and their free-list/inventory storage. Pool returns reserve no new storage at the cap; a failed factory inventory insertion destroys its unpublished candidate. Material, texture, render-target, CPU mesh and mesh-resource manager inventories also admit their retained array capacities. Owner unload releases inventory capacity; ordinary clear/erase keeps reusable capacity charged. Public caller-owned Array snapshots preserve their existing API and now carry the admitted allocation policy described below.

The Claw texture-cache map now admits its own object, sentinel, nodes and bucket arrays independently of pixels. Source paths and cooked-profile strings own allocation-local leases. Map creation is lazy, outside DLL initialization, and last-entry destruction frees the complete empty map without allocating replacement buckets. Pixel eviction retains charged cache metadata; wrapper destruction frees it. Float and cooked texture copies admit retained source capacity, including unused caller buffer capacity copied by Array, rather than only logical pixel lengths.

Generic engine object metadata also participates: TypeManager base-object and strong/weak control pools charge raw blocks, pool state/control allocations, block inventories and free-list capacity. All slots in a retained block remain charged. The full return queue is admitted before a block is published, so object destruction and slot reuse require no new allocation at capacity. Raw pool load/replacement stages its data and free list together. The shared allocation ledger exists before the streaming worker service; startup allocations do not start workers, and stopping/restarting that service preserves live reservations and configured limits.

TypeManager's type-name/label/hash/index/base/group/instance arrays, per-object type/flag tables, group-pool directories and reflection registry nodes/buckets also use SourceCpu admission. Growth stages the complete replacement before publication, including overlapping old/new capacity; denial preserves the old tables and consumes no type id. Reflection descriptors and their SharedPtr controls, retained type/member/key names and property/method map storage participate. Member insertion stages a complete callable descriptor before insertion. Retired reflection owners are destroyed outside the registry lock. Reflection callback capture and erased-value ownership now uses the admitted storage described below.

Reflection uses `Callback<Signature>`, `Any` and `Arguments` from `ReflectionStorage.hpp`. Each nonempty callback/value owns an aligned SourceCpu allocation for its typed state. Direct callbacks accept trivially copyable captures; owning captures use `Callback<Signature>::bind(function, captures...)`. Binding canonicalizes standard strings, vectors, engine Arrays and std::arrays recursively to SourceCpu-backed containers, preserving imported spare capacity. Nested Any values and standard engine Strings retain their own admitted ownership. Callback copies duplicate their physical state, while callback/value moves transfer storage without admission. Replacement stages complete state before publication; partial capture/payload failure unwinds its candidate and leaves the previous descriptor/value callable. Clearing and final destruction retire the physical allocation and its header/padding. Argument vector capacity is admitted too. Values escaping a getter or method keep their charge after the descriptor is destroyed.

`std::any` has no allocator hook. `Any::fromStdAny<T>(source)` checks the declared type and imports it into canonical storage; consuming imports reset the original only after complete success. The original caller-owned std::any remains outside reflection ownership until that boundary. Cast using `reflection::any_cast<Stored<T>>`; unsupported owning types require an audited `Storage<T>` canonical adapter. There is no unchecked opaque std::any/std::function or owning-lambda admission. Macros now use budgeted callbacks/values; setters explicitly copy to caller-owned object fields through `copyToExternal<T>`. Field storage uses that object's existing policy. Raw pointers/reference views are borrowed; their referents, arbitrary callback-body allocations and the existing constructed-object ownership policy remain separate allocation families. This closes the reflection-owned capture/value storage boundary, not the entire process heap. C++ reflection API consumers must rebuild and migrate legacy std::any callbacks to typed imports.

```cpp
using namespace workphone::reflection;
std::any legacy = std::vector<std::string>{"district", "facade"};
Any value = Any::fromStdAny<std::vector<std::string>>(legacy);
const auto &names = any_cast<const Stored<std::vector<std::string>> &>(value);
auto callback = Callback<Any(void *)>::bind(
    [](auto &captured, void *) -> Any { return captured; }, names);
Any escaped = callback(nullptr); // independently admitted payload ownership
```

The standard narrow/wide String character pools charge complete physical slabs, free-list/slab directories and size-class directory capacity, including unused blocks. Oversized buffers that bypass pooling use the same ledger. Returning every block and reusing spare blocks requires no admission; the full return capacity is reserved before publishing any slab, even when another slab still has live blocks. `CharacterPoolAllocator<T>::release_unused()` retires idle slabs and their per-bucket metadata without touching live strings; shared directory spare capacity remains charged while retained for other buckets. Standard pools keep their synchronization/storage shell alive for late static String destruction and retire late-returned idle buckets during shutdown. Explicit custom character upstream allocators retain their selected policy. Application-owned legacy StringPool data and free-list capacities also participate; denied replacement preserves the previous pool. Budget diagnostics allocate outside the budget mutex and fall back to an inline message if string growth is denied. C++ applications and dynamically loaded plugins must rebuild together for these table/pool layout changes.

State-context state/listener/event inventories, manager context/queue inventories and dispatch batches, and state-queue message capacities use SourceCpu admission. State/listener/context removal compacts in place; cleanup does not need a replacement inventory allocation at a full budget. Denied message enqueueing restores its previous context owner. Dirty-notification entries retain their existing allocator: notification follows message acceptance, so separate notification admission could strand an accepted message. ResourceDatabase instance arrays, UUID object registries and weak path caches also participate, including ordered-map block inventories and retained path strings. Existing path lookups compare caller strings directly, without admitting a temporary key. Registry replacement admits the complete candidate before publication, preserving previous identities on denial and releasing retired owners outside its lock. Catalog director-cache map capacity is admitted too.

SQLite eager results admit row/field capacities and retained field-name/value buffers. A read stages every row before publishing its result: allocation denial or a SQLite read error returns failure instead of a truncated successful query. Existing result owners and cursors remain usable, aliases share storage, and the final result owner releases its reservation. Bound, narrow and wide query paths admit generic query ownership metadata before executing SQL, preventing a mutation from committing and then losing its acknowledgement to metadata denial. Successful SQL mutations with no returned rows produce their empty acknowledgement without allocating result buffers. Detached Properties rows, fields, child lists and attribute snapshots now carry SourceCpu-backed public Array storage. SQLite's own page/statement heap remains a separate allocation family.

Normal Claw DX11 mesh geometry and texture uploads participate in the shared `Gpu` budget alongside terrain and foliage. GPU leases are attached to the physical D3D resources, so native/context references retain the reservation after wrapper unload. Reusing cached geometry does not reserve again. Replacement admission includes both generations and keeps the previous allocation on failure. Existing terrain/foliage texture wrappers delegate physical texture accounting to ClawTexture to avoid duplicate reservations.

Catalog pages, reference edges, document scan reports and their private authorization snapshots now admit their actual container capacity, allocation headers and overlapping replacements. Scan deduplication/candidate indexes, media inventory rows/identity sets, reference traversal/validation sets, document byte/text buffers, caller-owned binary serialization buffers and parse-work lists participate too. Properties field/child/attribute arrays and detached copies retain the policy; importing a raw caller property array first admits a complete replacement including spare capacity. Property-tree assignment stages both field and child arrays before changing either. Compilation dependency/dependent reads stage complete admitted snapshots and leave previous caller outputs intact on failure.

`makeSourceBudgetSnapshot<T>()` selects SourceCpu while preserving the existing public `Array<T>` type. Copies, moves, swaps, Array-to-std::vector snapshots, allocator rebinding and subsequent caller reserve/growth carry that allocation policy. Copies own separately admitted buffers; moves and shared authorization aliases transfer/share existing reservations. Clear/erase retains charged spare capacity; physical release retires it without new admission. Resource inventories, factory lists, state lists and existing asset-manager snapshots use the same policy. Ordinary raw caller arrays remain raw until explicitly imported through this boundary. The helper admits the container buffer; nested ownership is covered by the audited element policies (including Properties and already admitted nested arrays), not by arbitrary user-defined payloads. Explicit copies into external std::allocator containers and arbitrary object fields remain external allocations. Existing C++ clients/plugins must rebuild because the default allocator now carries a core-owned policy pointer; its raw default and public Array type names are preserved.

State/message dispatch admits retained context listener lists before marking a state clean or dequeuing messages. Denied dispatch leaves states/messages pending and keeps the context scheduled, including message-only contexts. State/factory/asset-manager teardown transfers existing inventories instead of copying them under a full budget. FactoryTemplate inventories now all use SourceCpu storage and reserve empty strong-reference teardown scratch before publishing an instance. Closing publication transfers that scratch and pins every instance under the inventory lock before callbacks; ordinary public snapshots admit separate caller buffers. Failed scratch/inventory growth destroys the unpublished candidate and retires staged storage. Instance retirement compacts raw pointers in place and erases only the tail, avoiding a temporary erase mask or replacement buffer; listener destruction no longer copies an unused diagnostic type name. Custom factory implementations with inventories must implement `takeInstanceObjectsForUnload()` to provide the same no-admission lifecycle guarantee.

StateQueue accepts messages directly into a synchronized SourceCpu array, including its spare capacity.
